# Локальные benchmark-результаты

## Среда и методика

Замеры выполнены 13 сентября 2026 года на Windows 11, Ryzen 7 8845HS, 31,31 GiB RAM и встроенной Radeon 780M. Runtime — Ollama 0.24.0, модель — единственная установленная `qwen3-coder:30b` (Q4_K_M, digest `sha256:06c1097efce0431c2045fe7b2e5108366e43bee1b4603a7aded8f21689e90bca`). Endpoint: `http://127.0.0.1:11434` на loopback.

Воспроизводимый запуск из корня проекта:

```powershell
.\scripts\benchmark-local-model.ps1
```

Скрипт проводит отдельный cold start для каждого `num_ctx` (4K, 8K, 16K), отправляет неизменный короткий Python prompt, устанавливает `temperature=0`, `seed=42`, `num_predict=128` и `keep_alive=0`. Метрики duration и числа токенов взяты непосредственно из ответа `POST /api/generate`; пик памяти — максимум среди процессов `ollama` с частотой опроса 200 мс. Модель завершала ответ после 49 сгенерированных токенов, поэтому это фактическая, а не целевая длина generation.

В TASK-005 отдельный инструментальный запрос при 16K показал `100% CPU`; Vulkan/offload на Radeon 780M не использовался. В текущих замерах runner выгружался после каждого прогона (`keep_alive=0`), поэтому модель не остаётся занимать RAM после завершения benchmark.

## Выводы и границы применимости

* Все три запрошенные конфигурации, включая 16K, успешно завершили cold start, prompt processing и generation. Для одного короткого запроса 16K — рабочая начальная конфигурация.
* При переходе 4K → 16K пик private memory вырос с 18,252 до 19,415 GiB. Это оставляет около 11,9 GiB от физической RAM до учёта Windows, VS Code, Jupyter и других процессов; запас нельзя считать гарантией для заполненного 16K контекста или многошагового agent loop.
* Generation стабильно около 19 ток/с, prompt processing около 64–67 ток/с в данном коротком prompt. Это не измерение качества кода, latency VS Code-интеграции или full-context throughput.
* 32K не проверялся: он не входит в утверждённую стартовую конфигурацию и требует отдельного решения после проверки реальной нагрузки агента. При memory pressure остаётся утверждённый fallback `num_ctx=8192`.

Следующая задача выбирает VS Code Agent; benchmark не подтверждает ни готовность sidebar-интеграции, ни полную offline-изоляцию.
