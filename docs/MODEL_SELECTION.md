# Выбор модели

## Решение

Основная локальная модель — **Qwen3-Coder-30B-A3B-Instruct** в официальном Ollama-варианте `qwen3-coder:30b` с quantization **Q4_K_M**. Начальный рабочий context — **16K токенов**; при нехватке памяти или нестабильности используется **8K**. Context 32K и Q5 не выбираются по умолчанию.

TASK-004 ничего не скачивала. Установка ровно одной выбранной модели относится к TASK-005, а фактическая скорость — к TASK-006.

## Почему выбран основной кандидат

Официальная карточка Qwen указывает 30,5B параметров всего, 3,3B активных на токен, 48 слоёв, 128 experts с активацией 8, 32 attention heads и 4 KV heads. Нативный context — 262 144 токена. Модель ориентирована на agentic coding, tool calling и Qwen Code, сохраняет общие и математические способности и распространяется по Apache-2.0. [Карточка Qwen3-Coder-30B-A3B-Instruct](https://huggingface.co/Qwen/Qwen3-Coder-30B-A3B-Instruct) и [публикация Qwen3-Coder](https://qwenlm.github.io/blog/qwen3-coder/)

Официальная библиотека Ollama предоставляет `qwen3-coder:30b` размером около 19 GB с Q4_K_M и пометкой `tools`. Это прямо совместимо с выбранным runtime без ручного импорта стороннего GGUF. [Qwen3-Coder в Ollama](https://ollama.com/library/qwen3-coder:30b)

MoE уменьшает объём активных вычислений на токен, но не размер всех загружаемых весов: для размещения всё равно требуются веса 30,5B. Поэтому 3,3B active нельзя трактовать как потребление памяти обычной 3B-модели.

## Оценка памяти

На хосте доступно 31,31 GiB общей RAM; Radeon 780M использует UMA и не имеет отдельного подтверждённого пула VRAM. Опубликованный Ollama-артефакт занимает около 19 GB на диске. Для планирования принят ориентир примерно **19–21 GiB** на веса и сопутствующие runtime buffers после загрузки; точное resident memory измеряется только после TASK-005.

Для FP16 KV-cache использована архитектура из официального `config.json`: 48 layers, 4 KV heads, `head_dim=128`. Расчёт на токен:

```text
2 (K и V) × 48 × 4 × 128 × 2 bytes = 98 304 bytes ≈ 96 KiB/token
```

| Context | Расчётный FP16 KV-cache | Вывод |
| --- | ---: | --- |
| 8K | около 0,75 GiB | Безопасный fallback |
| 16K | около 1,5 GiB | Начальная конфигурация |
| 32K | около 3,0 GiB | Только после замеров RAM и стабильности |

Это нижняя инженерная оценка самого KV-cache, а не полного процесса. Дополнительно нужны runtime buffers, Windows, VS Code, Jupyter, Conda и инструменты агента. При 16K ожидается тесный, но разумный запас; его необходимо подтвердить фактическим наблюдением. Q5 увеличит вес модели и уменьшит запас, поэтому сейчас не выбирается.

## Ожидаемая производительность

MoE с 3,3B active делает Qwen3-Coder-30B-A3B вычислительно привлекательнее dense 30B, но скорость на Ryzen 7 8845HS и Radeon 780M нельзя надёжно вывести из параметров. Vulkan/CPU hybrid inference поддерживается выбранным стеком, однако величина GPU offload, generation speed и prompt processing speed будут определены только реальным benchmark.

На TASK-006 необходимо измерить как минимум:

* время загрузки и resident RAM;
* prompt processing и generation в tokens/sec;
* фактический backend и распределение CPU/Vulkan;
* 8K и 16K context; 32K — только если остаётся безопасный запас памяти;
* устойчивость tool calling и многошагового agent loop.

## Baseline-модели

Baseline не скачиваются в TASK-004 и не являются выбранной основной моделью.

| Модель | Ollama Q4_K_M | Роль в сравнении |
| --- | ---: | --- |
| Qwen2.5-Coder-7B-Instruct | `qwen2.5-coder:7b`, около 4,7 GB | Нижняя граница RAM и latency; проверка цены качества основного кандидата |
| Qwen2.5-Coder-14B-Instruct | `qwen2.5-coder:14b`, около 9,0 GB | Более сильный compact baseline с заметно большим запасом RAM |

Обе модели специализированы на code generation, code reasoning и code fixing; официальные Ollama-теги также помечены поддержкой tools. [Qwen2.5-Coder 7B](https://ollama.com/library/qwen2.5-coder:7b) и [Qwen2.5-Coder 14B](https://ollama.com/library/qwen2.5-coder:14b)

Baseline разрешено устанавливать только отдельным будущим решением, если Qwen3-Coder-30B-A3B фактически не пройдёт memory/performance gate. TASK-005 по текущему решению скачивает только основную модель.

## Совместимость с целевым агентом

Qwen официально заявляет специальный function-call format и поддержку Qwen Code и других agentic coding tools. Ollama публикует модель с tools и предоставляет OpenAI-совместимый API. Это достаточное основание перейти к установке, но не доказательство полной notebook-интеграции: sidebar, native diff, terminal loop и изменение `.ipynb` проверяются в TASK-007–TASK-010.

Для статистического анализа ожидается полезность за счёт Python/coding и общих математических способностей. Специализированное качество статистических выводов официальными источниками здесь не подтверждено; его необходимо проверять на синтетическом примере и не принимать ответы модели без выполнения кода и проверки предпосылок.

## Риски и критерии отката

Основные риски: memory pressure из-за 19 GB весов, медленный prompt processing на больших context, нестабильный Vulkan offload на UMA и снижение качества tool calls после quantization.

Переход к compact baseline допускается только после фактического блокера:

* модель или 16K context не помещаются с работающими VS Code и Jupyter;
* 8K fallback тоже не обеспечивает устойчивый agent loop;
* generation/prompt processing непрактичны по результатам TASK-006;
* tool calling несовместим с выбранным endpoint или Agent layer.

Такой переход требует обновления этого решения; молчаливо заменять основную модель нельзя.

## Параметры для TASK-005

* модель: `qwen3-coder:30b`;
* ожидаемый артефакт: Q4_K_M, около 19 GB;
* одна модель, без одновременного скачивания baselines;
* начальный `num_ctx`: 16384;
* fallback при memory pressure: 8192;
* cloud-варианты запрещены;
* после установки проверить digest, license metadata, локальный API, tools и фактическое использование CPU/Vulkan.

## Фактический результат TASK-005

13 сентября 2026 года установлен ровно один артефакт `qwen3-coder:30b`: Q4_K_M, 30,5B, 18 556 700 761 bytes, digest `sha256:06c1097efce0431c2045fe7b2e5108366e43bee1b4603a7aded8f21689e90bca`. Локальные metadata Ollama подтвердили Apache-2.0 и capability `tools`.

Через `POST http://127.0.0.1:11434/api/chat` с `options.num_ctx=16384` модель успешно вызвала `get_project_status` без аргументов. Во время этого запроса `ollama ps` показал `100% CPU`, context 16 384 и размер загрузки 20 GB; runner занял 17,14 GiB working set / 18,73 GiB private memory. Vulkan/offload не был задействован. Это подтверждает возможность локальной загрузки и tools, но не заменяет benchmark TASK-006.
